# arXiv 논문 검색 · 저장 · 질의 — 요구사항

> **작성일**: 2026-10-30
> **브랜치**: feat/arxiv-paper-rag
> **상태**: 설계

## 1. 배경
지금 RAG(`rag_app`)는 사용자가 PDF를 직접 올려야 한다. 논문을 읽을 때는 arXiv에서 찾아 받아 올리는 과정이 반복되므로, 검색부터 저장 · 질의까지 한 화면에서 끝내고 여러 논문을 함께 질의하고 싶다.

## 2. 요구사항
- **R1 검색**: 키워드로 arXiv를 검색해 제목 · 저자 · 게시일 · 요약 · arXiv ID 목록을 보여 준다 (기본 10건)
- **R2 선택 다운로드**: 목록에서 고른 논문만 PDF를 git 제외 폴더에 받는다. 이미 받은 파일은 다시 받지 않는다
- **R3 저장**: 받은 PDF를 기존 파이프라인(청크 → 임베딩)으로 공용 컬렉션 `arxiv_papers`에 논문 단위로 누적 저장한다. 같은 내용 · 같은 설정으로 이미 저장된 논문은 건너뛴다
- **R4 질의**: 저장된 논문 전체 또는 고른 논문만 대상으로 질문하면, 근거 청크(논문 제목 · 페이지)와 함께 답한다
- **R5 화면**: 위 흐름을 Streamlit 페이지 하나에서 쓴다. 로직은 서비스 모듈에 두어 화면 없이도 호출할 수 있다
- **R6 실패 처리**: 검색 · 다운로드 · 저장 중 하나가 실패해도 다른 논문 처리와 이미 저장된 데이터에 영향이 없고, 실패한 논문은 다시 시도하면 정상 저장된다

## 3. 확정한 답
| 질문 | 답 |
|---|---|
| 사용 형태 | 서비스 모듈 + Streamlit 페이지 |
| 저장 단위 | 공용 컬렉션 하나, chunk metadata `arxiv_id`로 구분 |
| 논문 선택 | 검색 결과에서 사용자가 체크 |
| 사용 주체 · 권한 | 로컬 단일 사용자, 인증 없음 |
| 동시 요청 | 브라우저 탭 여러 개에서 같은 논문을 동시에 저장할 수 있음 → 중복 청크가 생기지 않아야 함 |
| 외부 호출 실패 | arXiv API는 `arxiv.Client` 재시도(3회, 3초 간격) 후 오류 표시. PDF 다운로드 실패는 해당 논문만 실패 처리 |
| 기존 데이터 호환 | 기존 컬렉션 · `save_to_store` 동작은 바꾸지 않음 |
| 이미지 읽기(OCR) | 끔 — arXiv PDF는 텍스트 PDF |

## 4. 미결 사항
- 비용 기록(`billing`) 연동은 이번 범위 밖
- 논문 삭제 기능은 이번 범위 밖 (필요 시 후속)
