# arXiv 논문 검색 · 저장 · 질의 — 요구사항

> **작성일**: 2026-10-30
> **브랜치**: feat/arxiv-paper-rag
> **상태**: 구현

## 1. 배경
지금 RAG(`rag_app`)는 사용자가 PDF를 직접 올려야 한다. 논문을 읽을 때는 arXiv에서 찾아 받아 올리는 과정이 반복되므로, 검색부터 저장 · 질의까지 한 화면에서 끝내고 여러 논문을 함께 질의하고 싶다.

## 2. 요구사항
- **R1 검색**: 키워드로 arXiv를 검색해 제목 · 저자 · 게시일 · 요약 · arXiv ID 목록을 보여 준다 (기본 10건). 행마다 원문 PDF 링크로 새 탭에서 바로 열 수 있다 (3차 추가)
- **R2 선택 다운로드**: 목록에서 고른 논문만 PDF를 git 제외 폴더에 받는다. 이미 받은 파일은 다시 받지 않는다
- **R3 저장**: 받은 PDF를 기존 파이프라인(청크 → 임베딩)으로 공용 컬렉션(`arxiv_papers_{임베딩 모델}_d{차원}`)에 논문 단위로 누적 저장한다. 같은 내용 · 같은 설정으로 이미 저장된 논문은 건너뛴다
- **R4 질의**: 저장된 논문 전체 또는 고른 논문만 대상으로 질문하면, 근거 청크(논문 제목 · 페이지)와 함께 답한다
- **R5 화면**: 위 흐름을 Streamlit 페이지 하나에서 쓴다. 로직은 서비스 모듈에 두어 화면 없이도 호출할 수 있다
- **R6 실패 처리**: 검색 · 다운로드 · 저장 중 하나가 실패해도 다른 논문 처리와 이미 저장된 데이터에 영향이 없고, 실패한 논문은 다시 시도하면 정상 저장된다
- **R7 PDF 미리보기**: 검색 결과 · 저장된 논문의 PDF를 화면에서 바로 본다. 받지 않은 논문은 미리보기 때 다운로드한다. 보고 난 뒤 닫을 수 있다 (구현 중 추가 요청)
- **R8 스캔 PDF OCR**: 저장할 때 페이지마다 텍스트 레이어가 있는지 검사해 PDF 유형(텍스트 · 이미지 · 혼합)을 판별하고, 텍스트가 없는 이미지 페이지만 LLM(Gemini)으로 OCR한다. 화면에 유형과 OCR 쪽수를 표시한다 (2차 추가)
- **R9 top-k 5**: 질의 시 근거 청크 5개를 쓴다 (2차 추가)
- **R10 하이브리드 검색**: 의미 검색(임베딩)과 키워드 검색(BM25)을 함께 써서 결과를 합친다. 한국어 질문도 영어 논문에서 키워드 검색이 되게 한다 (2차 추가)
- **R11 논문 삭제**: 논문 화면에서 저장된 논문을 하나씩 삭제한다 (청크 · 기록, 받아 둔 PDF는 캐시로 남김). 현재 임베딩 모델의 논문 컬렉션만 대상 — 이전 모델 컬렉션 정리는 후속 (2차 추가)
- **R12 기존 데이터 이전**: 수정 전 이름(`arxiv_papers`)으로 저장된 논문을 재임베딩 없이 새 컬렉션 이름 · 세대 표시 규칙으로 옮긴다 (2차 추가)

## 3. 확정한 답
| 질문 | 답 |
|---|---|
| 사용 형태 | 서비스 모듈 + Streamlit 페이지 |
| 저장 단위 | 공용 컬렉션 하나, chunk metadata `arxiv_id`로 구분 |
| 논문 선택 | 검색 결과에서 사용자가 체크 |
| 사용 주체 · 권한 | 로컬 단일 사용자, 인증 없음 |
| 동시 요청 | 브라우저 탭 여러 개에서 같은 논문을 동시에 저장할 수 있음 → 중복 청크가 생기지 않아야 함 |
| 외부 호출 실패 | arXiv API는 `arxiv.Client` 재시도(3회, 3초 간격) 후 오류 표시. PDF 다운로드 실패는 해당 논문만 실패 처리 |
| 기존 데이터 호환 | 기존 컬렉션 · `save_to_store` 동작은 바꾸지 않음 |
| 이미지 읽기(OCR) | 끔 — arXiv PDF는 텍스트 PDF |
| 재저장 실패 시 (리뷰 후 확정) | 기존 버전을 유지하고 계속 질의 가능해야 함 |
| 임베딩 모델 변경 (리뷰 후 확정) | 컬렉션 이름에 모델 · 차원을 넣어 분리 |
| 논문 버전 v1 · v2 (리뷰 후 확정) | 별개 논문으로 저장 |
| 기존 PDF RAG 화면 (리뷰 후 확정) | arXiv 컬렉션을 선택 · 삭제 목록에서 빼고, 이름을 직접 입력해 저장하면 거부 |
| 보호 위치 (재리뷰 후 확정) | `pipeline.save_to_store`에서 거부 — OCR 평가 화면 등 모든 경로. 판별은 이름이 아니라 컬렉션 metadata의 논문 기록(`papers`) |
| 모델 변경 시 안내 (재리뷰 후 확정) | 이번 범위 밖 — 후속 |
| OCR 판별 단위 (2차) | 페이지별 — 글자 수가 기준 미만이고 이미지가 있는 페이지만 OCR (텍스트 PDF는 LLM 호출 0) |
| 하이브리드 구현 (2차) | LangChain `BM25Retriever` + PGVector, `EnsembleRetriever`의 가중 RRF로 결합 |
| 세대 id (2차 리뷰 후 확정) | 저장마다 고유 `generation`을 붙이고 `index_key`는 건너뛰기 판단에만 사용. 이미 옮긴 데이터는 `generation = index_key`로 한 번 더 이전 |
| OCR 모델 (2차 리뷰 후 확정) | `ARXIV_OCR_MODEL` 따로 (기본값은 답변 모델), 출력 한도는 `IMAGE_MAX_OUTPUT_TOKENS` |
| 질문 언어 (2차) | 질문에 한글이 있으면 LLM으로 영어 검색 키워드를 만들어 BM25에만 사용, 의미 검색은 원문 질문 |

## 4. 미결 사항
- 비용 기록(`billing`) 연동은 이번 범위 밖
- 임베딩 모델을 바꾸면 논문 화면이 "저장된 논문 0편"으로 보임 (이전 논문은 이전 모델 컬렉션에 남음). 안내 · 정리 기능은 후속
- 확인 필요(최종 리뷰): OCR 평가 화면에 논문 컬렉션 이름을 입력하면 OCR · 임베딩 비용을 쓴 뒤 `save_to_store`에서 거부됨 (데이터 손실은 없음)
- 리스크(R8): 텍스트 논문에서도 글자가 50자 미만인 전면 그림 페이지는 스캔 페이지로 보고 OCR함 (그림 속 글자를 얻지만 그만큼 비용)
- 리스크(R10): 한글 질문의 키워드 변환은 답변 모델을 한 번 더 부름 (`gemini-3.8-flash` 할당량 429 상태에서는 질의 자체가 실패). 실제 Gemini로 하이브리드 질의 전체는 아직 돌려 보지 못함 — 실제 논문 2편으로 BM25 검색만 확인
- 확인 필요(2차 재리뷰): 세대 id를 채우지 않은 다른 DB에서는 옛 기록이 목록에는 보이지만 질의 대상에서 빠짐 (`backfill_generation()` 실행 필요). 화면 안내는 후속
- 2차 리뷰 Minor 미반영: BM25 캐시 스레드 안전성(여러 탭 동시 질의 시 KeyError 가능), OCR 빈 응답 캐시 · 비원자 쓰기, 저글자 페이지가 하나라도 있으면 전체 이미지 디코딩, `delete_paper` 두 연결, 이전 시 벡터 차원 검사 없음
- 코드 리뷰 Minor는 보고만 함 (커밋 메시지 · 최종 보고 참고). 주요 항목: 다운로드 간 3초 간격 없음, 질문 버튼 두 번 클릭, 저장 결과가 다음 상호작용에서 사라짐, 첫 저장 동시 실행 시 컬렉션 생성 IntegrityError 가능
- 리스크: 실제 Gemini 임베딩 · 답변으로 화면 전체를 돌려 보지 못함 (테스트는 가짜 임베딩 · LLM, `gemini-3.8-flash` 할당량 429). 실제 arXiv 검색 · 다운로드 · 파싱(90청크)은 확인함
