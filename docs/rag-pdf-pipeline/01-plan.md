# PDF RAG 실습 앱 기획안

| 항목 | 내용 |
| --- | --- |
| 브랜치 | `feature/rag-pdf-pipeline` |
| 위치 | [`rag_app/`](../../rag_app/) |
| 실행 | `uv run streamlit run rag_app/app.py` |
| 작성일 | 2026-10-27 |

## 1. 배경

`web_chat.py`는 모델 지식이나 웹 검색(Grounding)으로 답한다. 사내 문서처럼 **모델이 모르는 자료**를 근거로 답하려면 RAG(Retrieval-Augmented Generation)가 필요하다.
RAG는 "문서를 미리 쪼개 벡터로 저장해 두고(인덱싱), 질문이 오면 관련 조각을 찾아 프롬프트에 넣어 답하게(런타임)" 하는 구조인데, 단계가 많아 결과만 보면 어디서 품질이 떨어지는지 알기 어렵다.

## 2. 목표

1. LangChain으로 RAG 파이프라인 전체를 구현한다.
2. **각 단계의 출력값을 화면에서 바로 확인**할 수 있게 해, 청크 크기 · top-k · 지시문이 결과에 주는 영향을 눈으로 비교한다.
3. 기존 인프라(Vertex AI Gemini, 도커 PostgreSQL)를 그대로 재사용한다.

## 3. 범위

### 포함

| 구분 | 단계 | 화면에서 확인하는 출력 |
| --- | --- | --- |
| A. 미리 준비하기 (인덱싱) | A-1 문서 읽기 | 페이지 수, 페이지별 글자 수 · 변환한 이미지 수 · 원문, metadata, 글자 없는 페이지 · 이미지 변환 실패 경고 |
| | A-2 청크로 나누기 | 청크 수, 길이 분포 차트, 청크 원문과 다음 청크(겹침 영역) |
| | A-3 임베딩하기 | 벡터 수, 차원, 청크별 벡터 앞 8개 값 |
| | A-4 벡터 스토어 저장 | DB에 실제로 저장된 행 (id · 원문 · 출처 · 벡터 차원 · 벡터 미리보기) |
| B. 질문에 답하기 (런타임) | B-1 질문 입력 | 질문 벡터 (차원, 앞 10개 값) |
| | B-2 관련 청크 검색 | 순위별 코사인 거리 · 유사도 · 페이지 · 원문 |
| | B-3 프롬프트 구성 | LLM에 보내는 system / human 메시지 전문 |
| | B-4 LLM → 답변 | 답변 본문, 입력 · 출력 토큰 |
| | 체인 (선택) | B-1~B-4를 LCEL 체인 하나로 실행한 결과 (단계별 실행과 비교) |

### 포함 — OCR · RAG 평가 화면 (`rag_app/pages/ocr_eval.py`)

| 단계 | 화면에서 확인하는 출력 |
| --- | --- |
| OCR · 인덱싱 | 원본 페이지 이미지와 OCR 결과 나란히 비교, 쪽별 글자 수, 실패 쪽, 캐시 사용 여부, 저장된 청크 수 |
| 질문 · 정답 | 평가 세트 표(수정 · 저장), Gemini로 새로 생성 |
| RAG 평가 | 점수 · 정답/부분/오답 · 정답 쪽 검색률 · MRR · 답변 시간, 문항별 판정 · 검색된 쪽 · 판정 이유 |
| 실행 비교 | 설정별 실행 결과 표 · 차트 |

### 제외

- PDF 외 문서 형식 (Word, HTML, 이미지 등) — 업로드 단계에서 차단
- 이미지를 벡터로 직접 임베딩(멀티모달 검색) — 이미지는 Gemini가 만든 텍스트로만 검색
- 여러 문서 동시 인덱싱, 대화형(멀티턴) 질의, 사용자 인증

## 4. 요구사항

### 기능 요구사항

| ID | 요구사항 |
| --- | --- |
| FR-1 | PDF만 입력받는다. 업로더 확장자 제한(`.pdf`)과 파일 헤더(`%PDF-`) 검사를 함께 한다. |
| FR-2 | 그림의 8단계를 각각 실행하고, 단계마다 출력값을 화면에 표시한다. |
| FR-3 | 임베딩과 이미지 읽기는 Google Gemini(Vertex AI)를 사용한다. 답변 모델은 Gemini 또는 로컬 Ollama Gemma(`gemma4:e2b`) 중 선택한다. |
| FR-4 | 벡터 스토어는 `docker-compose.yml`로 띄운 PostgreSQL(pgvector)을 사용한다. |
| FR-5 | 사용자가 사이드바에서 설정값을 바꿀 수 있다: 이미지 읽기 on/off · 프롬프트, 청크 크기, 청크 겹침, 임베딩 모델 · 차원, 컬렉션 이름, top-k, 답변 모델, 출력 토큰 상한, 지시문. |
| FR-6 | 설정이 마지막 인덱싱과 달라지면 재인덱싱이 필요하다고 경고한다. |
| FR-7 | 같은 컬렉션에 다시 인덱싱하면 기존 청크를 지우고 교체한다(중복 저장 금지). |
| FR-9 | PDF 속 이미지(스캔 페이지 · 도표 · 그림)를 Gemini로 글자 추출 · 설명해 그 페이지 본문에 붙인다. 사이드바에서 끌 수 있다. |
| FR-10 | 글자가 없는 페이지, 변환하지 못한 이미지는 조용히 빠지지 않고 화면에 경고한다. |
| FR-11 | 파일 내용(sha256)과 저장 결과를 바꾸는 설정이 마지막 인덱싱과 같으면 API 호출 없이 건너뛴다. 이전 인덱싱에 이미지 변환 실패가 있었거나 저장이 불완전하면 건너뛰지 않으며, 사용자가 강제로 다시 인덱싱할 수 있다. |
| FR-12 | 스캔 PDF를 Gemini(`gemini-3.8-flash`)로 OCR한다. 인쇄 텍스트만 받아 적고 사진 · 그림 · 지도 안의 글자와 그림 설명은 제외한다. |
| FR-13 | 문서 기반 질문 · 정답 세트(답 있음 20 + 답 없음 4)로 RAG 답변을 답변과 다른 Gemini 모델이 채점하고, 정답 쪽 검색 여부 · 순위, 근거 충실도, 거절 정확도를 함께 측정한다. 사람 판정과 LLM 채점 일치율을 볼 수 있고, 설정별 결과를 비교할 수 있다. |
| FR-8 | 인덱싱 결과는 DB에 남아, 앱을 다시 켜도 B 탭에서 바로 질문할 수 있다. |

### 비기능 요구사항

| ID | 요구사항 |
| --- | --- |
| NFR-1 | 임베딩 API는 청크당 한 번만 호출한다 (3단계에서 만든 벡터를 4단계 저장에 재사용). `gemini-embedding-2`는 배치를 지원하지 않으므로 동시 요청으로 처리한다. 같은 텍스트의 벡터는 캐시(`embedding_cache`)에서 재사용한다. |
| NFR-2 | 기존 `web_chat.py`와 대화 데이터에 영향을 주지 않는다 (같은 DB, 별도 테이블). |
| NFR-3 | 인증 만료 · DB 미실행 등 흔한 오류는 해결 방법과 함께 화면에 안내한다. |

## 5. 기본 설정값

| 설정 | 기본값 | 변경 | 근거 |
| --- | --- | --- | --- |
| PDF 속 이미지 | Gemini로 글자 추출 · 설명 | 사이드바 | 스캔 PDF는 이 옵션 없이는 텍스트가 0자. 이미지가 없는 PDF는 호출 비용 없음 |
| 이미지 읽기 프롬프트 | 글자 원문 받아 적기 + 도표 · 그림 설명 (`IMAGE_PROMPT`) | 사이드바 (비우면 기본값) | 표는 마크다운 표로, 코드 블록 기호 없이 내용만 |
| 이미지 동시 요청 · 최소 크기 | 4개 · 64px | `RAG_IMAGE_CONCURRENCY` · 코드 | 페이지 많은 스캔 PDF의 처리 시간 단축, 아이콘 · 로고는 호출 생략 |
| 청크 크기 | 1000자 | 사이드바 (100~8000) | 한 문단 ~ 반 페이지. 검색 정밀도와 문맥 보존의 일반적인 절충점 |
| 청크 겹침 | 200자 | 사이드바 (0~2000) | 청크 크기의 20%. 경계에서 잘린 문장을 앞뒤 청크가 함께 보유 |
| 임베딩 모델 | `gemini-embedding-2` | 사이드바 · `RAG_EMBEDDING_MODEL` | Vertex AI의 Gemini 임베딩 모델 |
| 임베딩 차원 | 768 | 사이드바 (768 / 1536 / 3072) | 기본 3072 대비 저장 공간 1/4, 검색 품질 손실은 작음 |
| top-k | 4 | 사이드바 (1~20) | 1000자 × 4 ≈ 4000자 근거. 프롬프트가 과하게 길어지지 않는 수준 |
| 답변 모델 | Gemini Flash | 사이드바 (Gemini Flash / Gemma 4 로컬) | `web_chat.py`와 같은 선택지. Gemma는 로컬 실행 · 무료 |
| Gemini 모델 ID | `GEMINI_MODEL` (기본 `gemini-3.8-flash`) | 사이드바 · `RAG_LLM_MODEL` | Gemini 답변과 이미지 읽기에 사용 |
| 사고 수준 | `low` | 코드 | 근거를 읽고 정리하는 작업이라 깊은 추론 불필요 |
| 출력 토큰 상한 | 4096 | 사이드바 | Gemini는 추론 토큰 포함 |
| 컬렉션 이름 | `rag_pdf` | 사이드바 · `RAG_COLLECTION_NAME` | 컬렉션 별로 다른 문서 · 설정을 나눠 저장 |
